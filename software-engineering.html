Artifact Overview

The artifact I selected is the Travlr Getaways full-stack web application that I originally created during CS 465. The application uses a customer-facing website, an Angular administrative interface, a REST API, and a MongoDB database.

For the software design and engineering enhancement, I focused on improving the authentication and authorization system. The original application allowed authenticated users to reach administrative functions without distinguishing between normal users and administrators.

Enhancement

I added user roles to the application and included the role information inside the JSON Web Token. I then added role-based authorization to the API so administrative functions such as adding and editing trips require an administrator role.

On the Angular side, I created route guards that prevent unauthorized users from manually navigating to administrative pages. I also changed the interface so Add Trip and Edit Trip controls are only displayed to administrators.

I also improved the login process. The original code started the login request and then used a timed delay before checking whether authentication had completed. I changed this so the component waits for the actual authentication response before continuing.

Skills Demonstrated

Authentication and Authorization

The enhancement separates authentication, which determines who a user is, from authorization, which determines what the user is allowed to do.

Full-Stack Development

The enhancement required coordinated changes to the user model, JWT payload, API routes, Angular authentication service, route guards, and user interface.

Secure API Design

Administrative API endpoints are protected on the backend, so security does not depend only on hiding controls in the browser.

Testing and Validation

I tested the enhancement using both administrator and standard user accounts. Administrator users could see and use the Add Trip and Edit Trip controls, while standard users could not.

I also tested direct navigation to protected Angular routes. Standard users were redirected away from administrative pages. To verify that the API itself was protected, I sent a direct request using a standard-user token. The API returned a 403 Forbidden response, confirming that the authorization check could not be bypassed through the client interface.

Finally, I confirmed that an administrator could still edit and save trip information successfully after the security changes.

Course Outcome Alignment

This enhancement demonstrates progress toward Course Outcomes 3, 4, and 5. I evaluated the existing application design, selected an appropriate solution for separating authentication and authorization, and implemented the changes across multiple parts of the application.

The enhancement also demonstrates a security mindset by protecting administrative resources at both the interface and API levels instead of relying on client-side controls alone.

Reflection

One of the most important things I learned from this enhancement was the difference between proving who a user is and deciding what that user is allowed to do. The original project already used JWT authentication, but it did not separate standard users from administrators.

I also learned that authentication changes affect several layers of a full-stack application. The user model, token, API, Angular service, routing, and interface all had to agree on how the user's role was handled.
